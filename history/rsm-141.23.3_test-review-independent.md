## Evidence and coverage findings

### Medium: no generated role paragraph runs or post-drop joined runs

`tests/select_property_test.rs:33-39,82-131,200-222,642-646` generates matching tags (`a,b,c`) and an unknown control (`d`).
Sections can retain two adjacent paragraphs, so paragraph ranking is exercised there.
Roles have one blurb/group and at most one closing paragraph; selected blurb wordings occupy the fixed blurb slot, leaving no role run of length two.
There is no section paragraph after its bullets and no role paragraph pair around a bullet list.
The independent rank oracle is sound for the lists generated (`:785-789`), but cannot cover absent shapes.
Add `paragraph_runs_join_after_an_intervening_list_is_dropped`, parameterized for section and role: a tagged second paragraph rises across a fully dropped bullet list, while a retained list keeps the runs separate; assert output, baseline node indices, and kept-item positions.
Extend the generator with body paragraph vectors before and after bullet lists, including a guaranteed matching promote tag in a coverage witness.

### Medium: core-page order propagation has no promote-sensitive test

`src/pipeline.rs:163-197` clones selection into core-only, preserving promote today.
The searched core-page tests exercise drafts/preferences but supply no promote list; the directly inspected example is `tests/tailoring_test.rs:289-311`.
A page-count comparison on a normal short resume could pass even if order were ignored.
Add `core_pages_applies_promote_like_a_core_only_build`: use a test style whose page count depends on the first of two core bullets; compare measured pages with an explicit promoted core-only assessment, and assert that the empty-promote control has a different count.

### Low: the named inheritance example passes for the wrong reason

`a_bullet_ranks_by_the_tags_it_inherits_from_its_section_role_and_era` (`src/select/order_tests.rs:98-104`) has only an era tag; its expected `b a` follows from `b`'s own `lead` even without inherited `people`.
The role-cap test (`:105-112`) does distinguish inheritance, and the property oracle includes ancestor tags, so this is weak localized evidence, not wholly missing inheritance coverage.
Add `each_ancestor_caps_rank_before_stable_sort`, parameterized over section, role, era: inherited rank 1, untagged `a`, own-rank-2 `b`, own-rank-0 `c`, expected `c a b` (without the cap: `c b a`).

### Medium: missing mixed-origin build-plan regression

Separate end-to-end tests prove spec and profile origins work, but the hand-built `NameOrigins` unit fixture bypasses `build_plan::name_origins` (`src/commands/build_plan.rs:133-175`).
No inspected promote build test combines a selected tag overridden by a flag with that same tag promoted from a file, or repeats a promoted tag across profile and spec.
Add `promote_origins_survive_tag_overrides_and_spec_repetition`: profile promotes `shared,typo`, spec promotes `typo`, CLI overrides selected tags with `typo`; assert one flag warning, one spec promote warning at the spec line, one profile-only promote note, and no duplicate profile finding for `typo`.
This pins independence of the origin maps and the most-specific origin through the real plan, not just diagnostic formatting.

### Low: report properties discard duplicates and do not check exact metadata

The property test converts reported labels to a `BTreeSet`, then only checks position inequalities (`tests/select_property_test.rs:828-836`).
Duplicated movement records or incorrect but increasing positions can pass that property.
A precise role-bullet example exists (`src/select/order_tests.rs:270-303`, `the_report_names_each_list_that_changed_with_the_baseline_nodes_of_the_items_that_rose`), but paragraph and era records lack equivalent full assertions.
Add `paragraph_and_era_reports_name_exact_baseline_nodes_and_positions`; assert entire records after dropping an item, with multiple items rising, including container, kind, kept count, node index, and exact from/to.
Alternatively strengthen the property to compare a vector of expected records instead of a set of labels.

### Export is not a missing promote feature

`src/commands/export.rs:67-73` selects using CLI `SelectArgs`; `src/cli.rs:84-107` exposes no file-spec input for export.
The export regression `export_writes_the_selected_resume` checks filtering and wording (`tests/tailoring_test.rs:364-375`), not order.
Do not add promote plumbing merely to satisfy a test: this bead specifies spec-driven promotion, not a new export interface.
An optional `export_without_promote_preserves_authored_order` can assert exact exported paragraph/bullet order as a regression control.

## Root cause / mechanism

Most remaining gaps come from fixtures shaped like today's resumes rather than the full ordering domain.
A single trailing role paragraph never exercises a paragraph sort, and a page-count assertion cannot observe order unless the fixture makes order change pagination.
The report property loses multiplicity because it compares sets, while origin-formatting tests bypass the build-plan step that assigns those origins.
The observed paragraph failure has a direct mechanism: `ordered` returns its input for every paragraph list before computing ranks (`src/select/resume.rs:449-451`).
This is detected by three existing assertions, not a reason to add duplicate happy-path tests.

## Options

- Keep only the current examples: cheapest, but misses post-drop adjacency, promote-sensitive core measurement, and mixed-origin planning.
- Add focused discriminating cases and a small generator extension: best fit; covers the missing behavior without changing production boundaries.
- Duplicate every example as a CLI test or expand export's interface: higher maintenance cost without closing the most important gaps; not recommended.

## Recommendation

Do not sign off this tree as green while the paragraph bypass remains.
First establish whether it is a concurrent review mutation, then rerun the existing paragraph tests on the intended source.
Add the post-drop adjacency and promote-sensitive core-page tests first, then the mixed-origin build-plan case.
Strengthen the generator and report oracle rather than duplicating already-good blurb, JSON, and summary examples.
Correct the misleading inheritance fixture with the three-rank cap example.
No structural change or architecture diagram is warranted for this test review.
