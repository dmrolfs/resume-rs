## Root Cause / Mechanism

Paragraph ordering fails because the shared ordering entry point assumes paragraph lists should bypass sorting, while the caller and owner contract explicitly treat paragraph runs as orderable lists.
The `Slot` representation and run collection already provide the needed list boundary; the extra kind check disables that completed path.
This is a local contradictory guard, not a missing component or a reason to change the owner decision.

The other requested invariants hold on static inspection:

- Numbering: indices belong to the input walk, not sorted output positions.
  `from` and `to` count only kept list members; source lines use original indices.
- Blurb wording: `body.is_empty()` has the same meaning for slots as it had for final blocks.
  The blurb is never passed to `ordered`.
- Report order: sorting by the minimum moved node index is valid.
  Distinct surviving lists have nonoverlapping source-index ranges; a run that spans a dropped container spans no surviving movement record within that dropped container.
  Every emitted record has at least one moved node, so the optional minimum is always present.
- Idempotence: stable rank sorting is idempotent; promoted group wording retains union tags (`src/select/resume.rs:603-609`), inherited container tags survive, and applying selection again does not change rank.
  `src/select/order_tests.rs:256-267` and `tests/select_property_test.rs:845-849` assert repeat-selection identity.
  An idempotence test alone cannot catch finding 1, since doing nothing twice is also idempotent.
- Letters: `src/cli.rs:307-320` explicitly leaves promote empty.
  Their shared diagnostics therefore gain no promotion finding, their shared selection heading gains no promotion text, and their separate walker preserves body order even if a library caller supplies a nonempty promote field.
  This is a code-path argument, not a type-level prohibition on constructing such a selection.
- Core measurement: `src/pipeline.rs:182-187` clones selection and changes only scope, preserving promote for the core-only compile.
