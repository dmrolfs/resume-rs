DESCRIPTION

  ## Problem                                                                  
                                                                              
  Selection keeps and drops items but never moves them.                       
  In the evidence, the Org Leader draft reorders the shared bullets of 4 of 9 
  roles (HERE pipeline era, CDK, Rightside, Accenture) so leadership bullets  
  come first.                                                                 
  A role's first bullets are the ones a reader takes in, so one fixed order in
  the baseline leaves one audience with its strongest bullets lower down.     
                                                                              
  ## Purpose                                                                  
                                                                              
  A position spec (or profile) can say which tagged items come first, so one  
  baseline produces both orders.                                              
                                                                              
  ## Scope                                                                    
                                                                              
  In: an ordered promote = ["tag", ...] list in [select], merged like prefer  
  (most specific first, duplicates removed); applied after selection; the     
  summary line naming what moved.                                             
  Out: per-item order keys, moving items between containers, reordering       
  sections or roles.                                                          
                                                                              
  ## Rule                                                                     
                                                                              
  • Each item's rank is the position in promote of the first tag it carries,  
  after inheritance; an item with none of them ranks last.                    
  • Items are sorted by rank, stably, within their own container: a section's 
  direct items, a role's body, an era, a parent bullet's children. Nothing    
  moves across containers, and containers themselves keep their order.        
  • Alternates already resolved: the chosen variant takes the group's place.  
  • An empty promote changes nothing, so every existing spec is unaffected.   
  • A promote tag the file does not use warns and lists the file's tags, like 
  an unknown --tags value.                                                    
                                                                              
  Evidence for the rule (history/rsm-141.22_tailoring-decisions.md, Addendum  
  1): it reproduces the Org Leader draft's order exactly in all four roles;   
  CDK, Rightside, and Accenture need one tag each, the HERE pipeline era needs
  an ordered list of four.                                                    
                                                                              
  ## Implementation Plan (red first)                                          
                                                                              
  1. promote in the spec and profile types and the merge (rsm-141.23.1's      
  loader).                                                                    
  2. A pure order(Resume, &[Tag]) -> Resume, after select, with the rank rule 
  above.                                                                      
  3. The summary: items moved, per container.                                 
  4. User Guide: one worked example on the synthetic fixture.                 
                                                                              
  ## Test Plan                                                                
                                                                              
  [ ] The four draft orders: a fixture shaped like each reordered role, with  
  the promote list from the analysis, gives the target order exactly.         
  [ ] Property: output is a permutation of the input within each container; an
  empty list is the identity; order is idempotent; relative order of equal-   
  rank items is unchanged.                                                    
  [ ] Nothing crosses a container (a promoted bullet in a later role stays in 
  that role).                                                                 
  [ ] Unknown promote tags warn and list the file's tags.                     
  [ ] build --spec twice is byte-identical with promote set.                  
                                                                              
  Acceptance test: just check.
